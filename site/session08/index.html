🏭 הפייפליין המלא

⏱ 30 דקותמתקדםבכיתה

תרחיש אחד שאפשר להריץ שוב ושוב: לא מטפל פעמיים באותו ליד, מתעד הכול, שולח כל פנייה למקום הנכון, ולא נשבר כשה-AI טועה.

  1. גיליון טופלו: id · email · type · urgency · confidence · summary_he · תאריך טיפול
  2. משכפלים את תרגיל 4. אחרי ה-Iterator, לפני ה-AI: Google Sheets · Search Rows בגיליון טופלו · Filter: id Equal to id של הליד · Limit 1
  3. בין Search Rows ל-AI — פילטר "חדש": Row number של Search Rows · Basic operators: Does not exist. שימו לב: Search Rows שלא מוצא כלום עוצר את הליד (ראינו בבוט המלאי) — וכאן זה בדיוק הליד שאנחנו רוצים! בדקו בהגדרות המתקדמות של Search Rows אם יש אפשרות להמשיך גם בלי תוצאות. אין? ראו את הפתרון החלופי בדף הפתרונות
  4. קליק ימני על Parse JSON ← Add error handler ← Telegram "⚠️ ליד [id]: ה-AI החזיר תשובה לא תקינה" ← Ignore
  5. אחרי Parse JSON: Google Sheets · Add a Row ← טופלו (מתעדים לפני ה-Router, כדי שכל ליד יתועד)
  6. Router עם חמישה מסלולים:
    🔥 ליד חם · type = lead וגם urgency = high וגם confidence ≥ 0.7 ← Telegram
    🛠️ שירות · type = service ← Telegram "פניית שירות"
    🤔 לא בטוח · confidence < 0.5 ← Telegram "צריך בן אדם"
    🗑️ ספאם / קו"ח · type = spam או type = job ← בלי מודול (כבר תועד)
    📋 השאר · Fallback ← פילטר: יש email ← Gmail · Create a draft
  7. Run once על עמוד 3 ← ואז שוב Run once. בריצה השנייה — אף ליד לא אמור להגיע ל-AI
בריצה השנייה הכול רץ שוב

בדקו ש-Search Rows מחפש בעמודת id, ושהפילטר אחריו בודק שלא נמצא כלום. פתחו ב-History את הפלט של Search Rows בליד שכבר טופל: מה הוא החזיר?

זה תקין ב-Router: כל מסלול שהפילטר שלו מתקיים רץ. ליד שירות עם confidence 0.4 יקבל שתי הודעות. רוצים רק אחת? הוסיפו ל"לא בטוח" גם type ≠ service.
