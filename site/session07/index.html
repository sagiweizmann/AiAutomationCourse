פותחים בוט ב-Telegram

⏱ 5 דקותקלבכיתה

בוט משלכם, טוקן, ושיחה פתוחה איתו.

  1. ב-Telegram מחפשים @BotFather (עם ✔ כחול) ← Start
  2. שולחים /newbot ← שם: בית ועיצוב · לידים
  3. שם משתמש שנגמר ב-bot, למשל baitveitzuv_yourname_bot. תפוס? מוסיפים מספר
  4. BotFather שולח טוקן. מעתיקים אותו למקום בטוח זמני (לא לצ'אט!)
  5. לוחצים על הקישור לבוט החדש ← Start (או שולחים /start)
הטוקן = סיסמהדלף? ב-BotFather: /revoke ← בוחרים את הבוט ← טוקן חדש. ואז מעדכנים את החיבור ב-Make (Credentials ← Edit), כמו במפגש 6.

איך יודעים שעשיתם טוב

  • יש לי בוט, והוא מופיע בצ'אטים שלי
  • שלחתי לו /start

Make an API call: מוצאים את ה-chat_id

⏱ 10 דקותקלבכיתה

להשתמש ב"דלת האחורית" של מודול: קריאה ל-API שאין לה מודול, דרך החיבור הקיים.

  1. ב-Make: תרחיש חדש ← Telegram Bot ← Make an API Call
  2. Connection ← Add ← מדביקים את הטוקן ← Save
  3. URL: getUpdates · Method: GET ← Save
  4. קליק ימני ← Run this module only
  5. בפלט: Body ← result ← 1 ← message ← chat ← id. רושמים את המספר
result ריק?

לא שלחתם /start לבוט, או ששלחתם לבוט אחר. שלחו לו הודעה כלשהי, והריצו שוב.

איך יודעים שעשיתם טוב

  • יש לי chat_id — מספר בלי מירכאות
  • אני יודע/ת להסביר למה זו דרך 2 ולא מודול מוכן

HTTP: אותה הודעה, בלי מודול

⏱ 15 דקותבינוניבכיתה

לשלוח את אותה הודעה עם HTTP — כאילו אין ל-Telegram מודול ב-Make — ולהשוות.

  1. תרחיש חדש ← HTTP · Make a request
  2. URL: https://api.telegram.org/botהטוקן/sendMessage (שימו לב: bot צמוד לטוקן, בלי רווח)
  3. Method: POST · תוכן מסוג JSON (application/json)
  4. בתוכן: מדביקים את ה-JSON למטה, עם ה-chat_id שלכם
  5. Parse response = Yes ← Run once ← הודעה בטלפון?
  6. ממלאים את טבלת ההשוואה
{"chat_id": 123456789, "text": "שלום מ-HTTP 👋"}
שאלהמודול מוכןHTTP
איפה הטוקן?
מה קורה אם שוכחים chat_id?
מה היה קל יותר?
קיבלתי "ok": false

קראו את description בתשובה. "Not Found" = טעות בכתובת או בטוקן. "chat not found" = chat_id שגוי. "Bad Request: message text is empty" = text ריק או JSON שבור.

איך יודעים שעשיתם טוב

  • קיבלתי את ההודעה מ-HTTP
  • הטבלה מלאה
  • אני יודע/ת למה עדיף מודול מוכן כשיש

Webhook: ליד מ"טופס" נכנס ל-monday

⏱ 20 דקותבינוניבכיתה

Hoppscotch משחק את הטופס באתר. Make מקבל את הבקשה מיד, ויוצר ליד בלוח.

  1. תרחיש חדש ← Webhooks · Custom webhook ← Add ← שם: ליד מהאתר ← Save ← Copy address to clipboard
  2. לוחצים Run once — Make מחכה לבקשה
  3. ב-hoppscotch.io: POST · מדביקים את הכתובת · Body ← application/json ← ה-JSON למטה ← Send
  4. ב-Make: הבועה מעל ה-Webhook מראה את הנתונים. עכשיו יש בועות name, email, product, message
  5. מוסיפים monday.com · Create an Item (כמו בתרגיל 9 של מפגש 6): Item Name ← name, ו-Columns: אימייל, מוצר מבוקש, הודעה, סטטוס = ליד חדש
  6. Run once ← שוב Send ב-Hoppscotch ← הליד בלוח?
  7. בונוס: מודול Webhooks · Webhook response בסוף: Status 200, Body: {"ok": true, "message": "תודה, נחזור אלייך"}. ב-Hoppscotch תראו את התשובה
{"name": "תמר גולן", "email": "you+tamar@gmail.com", "product": "שולחן עבודה מעץ", "message": "יש משלוח לירושלים? צריכה עד יום חמישי."}
שיניתי את השדות ב-JSON, ו-Make לא רואה אותם

פותחים את ה-Webhook ← Redetermine data structure ← Send שוב מ-Hoppscotch.

איך יודעים שעשיתם טוב

  • תמר נוצרה בלוח עם אימייל, מוצר והודעה
  • אני יודע/ת להסביר מה ההבדל בין הטריגר הזה ל-Watch Board's Items
  • בדקתי את Webhooks ← Logs וראיתי את הבקשה

שלושה תרחישים שעובדים יחד: "טופס" ← monday ← Haiku ← Telegram + טיוטה.

  1. שולחים מ-Hoppscotch ליד חם: הודעה עם תאריך יעד קרוב ואיום במתחרה
  2. תרחיש תרגיל 5 יוצר אותו בלוח (Run once)
  3. תרחיש הלידים (תרגיל 3): Choose where to start ← Choose manually ← הליד שלפני ← Run once
  4. בודקים: ניתוח בלוח · טיוטה ב-Gmail · הודעה בטלפון
{"name": "אבי כהן", "email": "you+avi@gmail.com", "product": "ספה פינתית", "message": "אנחנו נכנסים לדירה בעוד 10 ימים וצריכים ספה. אם אתם לא יכולים — נזמין מאיקאה."}
מה הופך את זה לאמיתיאם שני התרחישים היו דולקים (Active), כל זה היה קורה לבד: ה-Webhook מיד, ותרחיש הלידים תוך 15 דקות. בתרגול — Run once, כדי לחסוך קרדיטים.

בונוס: הודעה לבוט ← ליד ב-monday

⏱ 20 דקותמתקדםבונוס

Webhook "אמיתי" מבחוץ: כל הודעה שנשלחת לבוט יוצרת ליד בלוח.

  1. תרחיש חדש ← Telegram Bot · Watch Updates (Instant). Make רושם Webhook אצל Telegram לבד
  2. Run once ← שולחים לבוט מהטלפון: "שמי דנה, מתעניינת בשולחן אוכל, dana@example.com"
  3. Haiku: "חלץ מההודעה JSON: name, email, product" ← Parse JSON ← monday Create an Item
  4. בונוס-בונוס: Send a Text Message or a Reply חזרה לשולח: "תודה! קיבלנו, נחזור אלייך"
שימו לבבוט עם Watch Updates לא יעבוד במקביל לבדיקת getUpdates מתרגיל 2: ברגע שיש Webhook, getUpdates מחזיר שגיאה. זה תקין — Telegram שולח לכתובת של Make במקום לשמור.
