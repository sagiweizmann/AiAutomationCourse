Webhook: ליד מ"טופס" נכנס ל-Google Sheets

⏱ 15 דקותבינוניבכיתה

Hoppscotch משחק את הטופס באתר. Make מקבל את הבקשה מיד, ומוסיף את הליד כשורה בגיליון.

  1. ב-Google Sheets: גיליון חדש לידים מהאתר, ובשורה 1 הכותרות: תאריך · שם · אימייל · מוצר · הודעה · סטטוס
  2. ב-Make: תרחיש חדש ← Webhooks · Custom webhook ← Add ← שם: ליד מהאתר ← Save ← Copy address to clipboard
  3. לוחצים Run once — Make מחכה לבקשה
  4. ב-hoppscotch.io: POST · מדביקים את הכתובת · Body ← application/json ← ה-JSON למטה ← Send
  5. ב-Make: הבועה מעל ה-Webhook מראה את הנתונים. עכשיו יש בועות name, email, product, message
  6. מוסיפים Google Sheets · Add a Row ← הגיליון לידים מהאתר ← Table contains headers: Yes ← ממפים: תאריך = now, שם ← name, אימייל ← email, מוצר ← product, הודעה ← message, סטטוס = ליד חדש (מקלידים)
  7. Run once ← שוב Send ב-Hoppscotch ← השורה של תמר בגיליון?
  8. בונוס: מודול Webhooks · Webhook response בסוף: Status 200, Body: {"ok": true, "message": "תודה, נחזור אלייך"}. ב-Hoppscotch תראו את התשובה
{"name": "תמר גולן", "email": "you+tamar@gmail.com", "product": "שולחן עבודה מעץ", "message": "יש משלוח לירושלים? צריכה עד יום חמישי."}
שיניתי את השדות ב-JSON, ו-Make לא רואה אותם

פותחים את ה-Webhook ← Redetermine data structure ← Send שוב מ-Hoppscotch.

איך יודעים שעשיתם טוב

  • תמר נוספה לגיליון עם אימייל, מוצר והודעה
  • אני יודע/ת להסביר מה ההבדל בין הטריגר הזה ל-Watch New Rows של Google Sheets
  • בדקתי את Webhooks ← Logs וראיתי את הבקשה
2

ראוטר חכם: ליד חם לטלפון, השאר לגיליון

⏱ 20 דקותבינוניבכיתה

אותו "טופס", אבל עכשיו Make מחליט לבד: ליד גדול או דחוף ← הודעה לנציג. כל השאר ← שורה ב-Google Sheets לטיפול מאוחר יותר. והשולח מקבל תשובה אחרת בכל מסלול.

  1. ב-Google Sheets: גיליון חדש לידים לטיפול, ובשורה 1 הכותרות: תאריך · שם · אימייל · מוצר · תקציב
  2. ב-Make: תרחיש חדש ← Webhooks · Custom webhook ← Add ← שם: ליד עם תקציב ← Save ← Copy address
  3. Run once, ושולחים מ-Hoppscotch את ליד A מלמטה — כדי ש-Make יכיר את השדות (כולל budget ו-urgent)
  4. מוסיפים Flow Control · Router אחרי ה-Webhook. יש לו שני מסלולים
  5. מסלול 🔥 ליד חם — קליק על הקו ← Set up a filter ← Label: ליד חם:
    תנאי 1: budget · Numeric operators: Greater than · 5000
    ← Add OR rule ← תנאי 2: urgent · Boolean operators: Equal to · true
  6. במסלול הזה: Telegram Bot · Send a Text Message or a Reply עם ה-chat_id שלכם. Text: כותבים 🔥 ליד חם: ואחריו גוררים את הבועות name, product, budget ו-urgent
  7. מסלול 📋 לגיליון — קליק על הקו ← Label: לגיליון ← Fallback route: Yes (רץ רק כשאף מסלול אחר לא התאים)
  8. במסלול הזה: Google Sheets · Add a Row ← הגיליון לידים לטיפול ← ממפים: תאריך = now, שם, אימייל, מוצר, תקציב
  9. בסוף כל מסלול: Webhooks · Webhook response · Status 200 · Body:
    🔥 {"ok": true, "message": "נציג יחזור אלייך תוך שעה"}
    📋 {"ok": true, "message": "קיבלנו! נחזור אלייך תוך 2 ימי עסקים"}

🎲 משחק: לאן כל ליד יגיע?

לפני כל שליחה — כתבו בטבלה את הניחוש שלכם. אחר כך Run once ← Send ב-Hoppscotch ← בודקים: הודעה בטלפון או שורה בגיליון? ומה Hoppscotch קיבל בתשובה?

B  {"name": "יוסי מזרחי", "email": "you+yossi@gmail.com", "product": "כיסא משרדי", "budget": 800, "urgent": true}

לידהניחוש שלי (🔥 / 📋)מה קרה בפועללמה?

B · יוסי
C · מיכל
D · דני
כל הלידים הולכים לאותו מסלול

בדקו שהאופרטור הוא Numeric ולא Text, ושבין שני התנאים יש OR (שתי קבוצות נפרדות) ולא AND (באותה קבוצה). ואם בטעות שני המסלולים בלי פילטר — שניהם ירוצו תמיד.

Make לא מכיר את budget או urgent

ה-Webhook למד את המבנה מהשליחה הראשונה. פותחים אותו ← Redetermine data structure ← Send שוב את ליד A.

אתגרהוסיפו מסלול שלישי 💎 VIP מעל 30,000: הודעה ב-Telegram וגם שורה בגיליון עם "VIP" בעמודה נוספת. איזה מסלול ירוץ לרונית עכשיו? (רמז: ליד יכול לעבור ביותר ממסלול אחד.)

איך יודעים שעשיתם טוב

  • ניחשתי את ארבעת הלידים לפני ששלחתי
  • A ו-B הגיעו לטלפון, C ו-D לגיליון
  • אני יודע/ת להסביר למה דני (5000 בדיוק) לא ליד חם
  • Hoppscotch קיבל תשובה שונה לכל מסלול

בוט מלאי: שואלים את הבוט, הוא עונה מהגיליון

⏱ 25 דקותבינוניבכיתה

הבוט שלכם הופך לנציג: לקוח כותב שם של מוצר, והבוט עונה מיד מה המחיר ואם יש במלאי — מתוך Google Sheets.

  1. ב-Google Sheets: גיליון חדש מלאי בית ועיצוב. מדביקים בתא A1 את הטבלה מלמטה (היא תתפרס לעמודות לבד)
  2. ב-Make: תרחיש חדש ← Telegram Bot · Watch Updates ← החיבור של הבוט שלכם ← Save. Make רושם את עצמו אצל Telegram
  3. מוסיפים Google Sheets · Search Rows ← הגיליון מלאי בית ועיצוב ← Table contains headers: Yes
    Filter: עמודה מוצר · Text operators: Contains (case insensitive) · Message › Text מהטריגר
    Maximum number of returned rows: 1
  4. מוסיפים Router עם שני מסלולים:
    ✅ יש במלאי — פילטר: מלאי · Numeric: Greater than · 0
    😕 אזל — פילטר: מלאי · Numeric: Equal to · 0
  5. בכל מסלול: Telegram Bot · Send a Text Message or a Reply
    Chat ID: Message › Chat › ID מהטריגר (לא המספר שלכם! עונים למי ששאל)
    ✅ Text: בועת מוצר, ואחריה "₪" + בועת מחיר, ו-"יש" + בועת מלאי + "במלאי ✅"
    😕 Text: בועת מוצר + "אזל מהמלאי 😕 נעדכן כשיחזור"
  6. Run once ← שולחים לבוט מהטלפון: ספה ← הבוט עונה? ← Run once ← כורסה
  7. 🤝 בזוגות: תנו לשותף את שם המשתמש של הבוט שלכם. הוא שואל, אתם מריצים — הבוט עונה לו, לא לכם
מוצר	מחיר	מלאי
ספה פינתית	6900	2
שולחן עבודה מעץ	1200	3
כורסה	2400	0
מדף ספרים	650	12
מנורת קריאה	320	0
שולחן אוכל	3800	1
שאלתי על "מזרן" והבוט לא ענה בכלל

זה לא באג. Search Rows לא מצא שורה ← יצא 0 bundles ← שום מודול אחריו לא רץ. בדקו בבועה של Search Rows: אין פלט. זו התנהגות של כל מודול חיפוש ב-Make.

הבוט לא מגיב, או ש-getUpdates מחזיר שגיאה

לבוט יכולה להיות כתובת Webhook אחת. אם יש תרחיש אחר עם Watch Updates על אותו בוט (למשל הבונוס) — כבו אותו, או פתחו בוט שני ב-BotFather לתרגיל הזה.

אתגרים (בחרו אחד) 1 · התראה לבעלים: במסלול 😕 הוסיפו הודעה נוספת ל-chat_id שלכם: "לקוח שאל על כורסה ואין במלאי". כך יודעים מה להזמין.
2 · הפקודה /הכל: Router מיד אחרי הטריגר. מסלול 1 עם פילטר Text Equal to /הכל ← Search Rows בלי פילטר ← Tools · Text aggregator (שורה לכל מוצר: בועות מוצר ומחיר) ← הודעה אחת עם כל הרשימה. מסלול 2 (Fallback) — החיפוש הרגיל.
3 · "לא מצאתי": גרמו לבוט לענות גם כשאין מוצר כזה. רמז: נסו Array aggregator אחרי Search Rows, ובדקו מה יוצא ממנו כשאין תוצאות.
בסוף התרגילWatch Updates הוא טריגר מיידי. אם הפעלתם את התרחיש (Active) — כבו אותו, אחרת כל הודעה לבוט עולה קרדיט.

איך יודעים שעשיתם טוב

  • הבוט ענה על "ספה" עם מחיר ומלאי
  • הבוט ענה על "כורסה" שאזלה
  • השותף שאל את הבוט שלי וקיבל תשובה
  • אני יודע/ת להסביר למה על "מזרן" אין תשובה
חזרה: מה שעשינו בכיתה
את אלה כבר בנינו ביחדתרגילים 4–8 הם מה שהדגמנו בכיתה: בוט, chat_id, הודעה ממודול וב-HTTP, והשרשרת המלאה. חסר לכם משהו מהם? כאן ההוראות המלאות, ובמדריך הבוט — צילומי מסך לכל שלב.

HTTP: אותה הודעה, בלי מודול

⏱ 15 דקותבינוניעשינו בכיתה

לשלוח את אותה הודעה עם HTTP — כאילו אין ל-Telegram מודול ב-Make — ולהשוות.

  1. תרחיש חדש ← HTTP · Make a request
  2. URL: https://api.telegram.org/botהטוקן/sendMessage (שימו לב: bot צמוד לטוקן, בלי רווח)
  3. Authentication type: No authentication · Method: POST
  4. Body content type: application/json · Body input method: JSON string
  5. Body content: מדביקים את ה-JSON למטה, עם ה-chat_id שלכם
  6. Parse response = Yes ← Run once ← הודעה בטלפון?
  7. ממלאים את טבלת ההשוואה

השרשרת המלאה

⏱ 15 דקותמתקדםעשינו בכיתה

שני תרחישים שעובדים יחד: "טופס" ← גיליון ← Haiku ← Telegram.
