כללי אצבע

שישה כללים לחיבור אפליקציות

  1. תמיד מחפשים מודול מוכן קודם. HTTP — רק כשאין.
  2. מפתחות בחיבור, לא בשדות. אם המפתח בכתובת (כמו ב-Telegram) — לא משתפים את התרחיש.
  3. בתיעוד מחפשים חמישה דברים: פעולה, שיטה, כתובת, פרמטרים חובה, דוגמת תשובה.
  4. Webhook עדיף על Polling כשהאפליקציה תומכת: מהיר וזול.
  5. כתובת Webhook לא מפרסמים. אפשר לבדוק שדה סודי בפילטר.
  6. לכל תרחיש: שם, תיאור, מי אחראי — ומה עושים כשהוא נשבר.
בדיקה עצמית

6 שאלות: מה נשאר לכם מהמפגש?

1. לאפליקציה יש מודול ב-Make, אבל לא לפעולה שאתם צריכים. מה עושים?
הסבר: Make an API call משתמש בחיבור שכבר יש, ומאפשר כל פעולה מהתיעוד. HTTP אפשרי, אבל אז צריך לטפל במפתח בעצמכם.
2. מה ההבדל העיקרי בין Webhook ל-Polling?
הסבר: Webhook = פעמון, Polling = לבדוק את תיבת הדואר. Webhook מהיר ולא עולה על בדיקות ריקות.
3. getUpdates מחזיר result ריק. למה?
הסבר: בוט לא יכול לפנות ראשון. בלי הודעה מכם — אין עדכונים, ואין chat_id. (טוקן שגוי היה מחזיר שגיאה, לא רשימה ריקה.)
4. למה מודול מוכן עדיף על HTTP כשיש?
הסבר: ב-HTTP של Telegram הטוקן בכתובת, גלוי לכל מי שרואה את התרחיש. והמודול מסמן שדות חובה לפני שרצים.
5. שיניתם את ה-JSON ששולחים ל-Webhook (הוספתם phone), ו-Make לא מציע בועה phone. מה עושים?
הסבר: Make למד את השדות מהבקשה הראשונה. Redetermine אומר לו ללמוד מחדש מהבקשה הבאה.
6. "הזמנה מעל 5,000 ₪ ← הודעה מיידית למנהל". איזה טריגר ודפוס?
הסבר: "מיידית" = Webhook. פילטר על הסכום = ניתוב. הודעה למנהל = התראה.
