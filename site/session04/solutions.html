מודול AI ראשון: Haiku מסווג פנייה

שרשרת המודולים
  • Sheets · Watch new rows (כמו בתרגיל 2)
  • AI by Make · Simple Text Prompt — Make's AI Provider (default), Anthropic: Claude Haiku 5.5. בשדה Text: הוראות הסיווג מדף התרגול, ומתחתן בועת message
  • Router עם שלושה ענפים: ענף "מכירות" — תשובת ה-AI Contains מכירות ← מייל "ליד חדש" · ענף "תלונה" — תשובת ה-AI Contains תלונה ← מייל "⚠️ תלונה" · Fallback ← מייל "לבדיקה" (כאן נוחתת התמיכה)
פנייהמה Haiku אמור להחזירלמה
רונית — "כמה עולה מערכת הזמנות…"מכירותשאלה על מחיר ומוצר
אבי — "המערכת לא שולחת תזכורות…"תמיכהמשהו לא עובד במערכת קיימת
מיכל — "כבר שבוע מחכה… ממש לא בסדר"תלונהכעס על השירות
תקלה: ה-AI מחזיר משפט ("הפנייה שייכת לקטגוריית מכירות")עם Contains זה עדיין יעבוד — אבל זה סימן שההוראות לא חדות. השורה "החזר מילה אחת בלבד מתוך שלוש המילים, בלי נקודה ובלי הסבר" חייבת להיות האחרונה בהוראות.
תקלה: הכול הולך ל-Fallbackהפילטרים עדיין משווים לעמודת type מהגיליון במקום לבועת התשובה של מודול ה-AI. פותחים כל פילטר ובוחרים מחדש את השדה — מהמודול של ה-AI, לא מהטריגר.
תקלה: מודול ה-AI הוא אחרי ה-Routerאז לפילטרים אין תשובה להשוות אליה. ה-AI חייב לבוא לפני ה-Router: קליק ימני על הקו שביניהם ← Add a module.
למה שווה לחשוב על זה כ"ה-AI מחליט, Make מבצע"Haiku לא שולח שום מייל ולא יודע שיש Router. הוא רק מחזיר מילה. כל ההשלכות — מי מקבל מה — נשארות בידיים שלכם, בפילטרים.

מה Claude Haiku כתב בהרצה שלנו

הטקסט האמיתי מהטיוטות. אצלכם הניסוח יהיה אחר — ה-AI כותב כל פעם מחדש, וזה תקין.

שלום דנה, ציינת שההזמנות מגיעות אליכם בוואטסאפ, ובחגים זה נהיה כאוס מוחלט. מערכת ההזמנות מרכזת את כל ההזמנות במקום אחד ומסדרת אותן לפי תאריך ואיסוף. כך פחות הזמנות נופלות בין ההודעות, וגם בשיא החגים אפשר לדעת בדיוק מה צריך להכין. אשמח להציע שיחה קצרה של 15 דקות השבוע, כדי להבין איך זה יכול להתאים למאפייה שלכם ולענות על כל השאלות שיש לכם. בברכה, נועה, אוטומט
שלום יוסי, תודה שהשארת פרטים באתר. אתה מתאר מצב מוכר: לקוחות שוכחים את הטיפול השנתי ואז מתקשרים בלחץ. מערכת התזכורות של אוטומט שולחת ללקוחות שלך הודעה מראש לפני מועד הטיפול השנתי, כך שהם מגיעים בזמן ולא נדחקים לרגע האחרון. בנוסף, המערכת עוזרת לך לנהל את לוח הזמנים של המוסך בצורה מסודרת ורגועה יותר. אשמח להציע שיחה של 15 דקות השבוע, כדי להבין את הצרכים של מוסך לוי ולהראות לך איך זה יכול להתאים לך. מתי נוח לך? נועה, אוטומט
כמה זה עלהמודול ה-AI: 2 operations · 3.26 credits — כ-1.6 קרדיטים למייל. למייל של דנה: 565 טוקנים נכנסים, 1,094 יוצאים.

שער הדולר → מגמה ומסקנה

השרשרתGoogle Sheets · Search Rows (יומן דולר, Limit = 7) ← Tools · Text aggregator ({{date}}: {{rate}}; Row separator = New row נמצא תחת Show advanced settings) ← Simple Text Prompt ← Gmail.

נבדק בהרצה אמיתית. התשובה של Haiku:

המגמה: עולה, אם כי נרשמה ירידה קלה ביום 29.10. השער נע בין 3.118 ל-3.157 שקלים לדולר. בין 28.10 ל-3.11.2026 השער עלה ב-0.036 שקלים, כלומר בכ-1.15%, מ-3.121 ל-3.157 שקלים. משמעות: הזמנה של 10,000 דולר מספק בחו"ל עולה כעת כ-31,570 שקלים, לעומת כ-31,210 שקלים בתחילת התקופה, כלומר תוספת של כ-360 שקלים.
תקלה: ה-AI כתב "עלייה של 1.5%"זו בדיוק הסיבה לכלל "Make מחשב, AI מסביר". הוסיפו לגיליון תא =(B6-B2)/B2, או חשבו ב-Make: {{formatNumber((last - first) / first * 100; 2; ".")}} — והעבירו ל-AI את התוצאה כנתון.
תקלה: ה-AI ממליץ "כדאי לקנות דולרים עכשיו"חסרה (או לא מספיק חזקה) השורה "אל תיתן המלצות השקעה ואל תנבא". זה לא רק סגנון — זו אחריות: אוטומציה לא צריכה לייעץ ייעוץ פיננסי.

תדריך בוקר: שני מקורות, מייל אחד

השרשרתHTTP מזג אוויר (Parse = No) ← HTTP דולר open.er-api.com/v6/latest/USD (Parse = Yes) ← Simple Text Prompt ← Gmail. בפרומפט: Data של מזג האוויר, ו-data: rates: ILS של מודול הדולר.

נבדק בהרצה אמיתית. התשובה של Haiku (בלי התגיות):

🚚 הובלות מזג האוויר: מקסימום 26.4°C, מינימום 17.5°C, ללא משקעים (סיכוי 3%) ורוח עד 14.1 קמ"ש. המלצה: תנאים מתאימים להובלות, ומומלץ לתזמן אותן ללא חשש ממשקעים. 💵 רכש שער הדולר היום עומד על 3.164 ₪ לדולר.
תקלה: מודול הדולר נתקע ב-"Running…"זה קרה לנו עם frankfurter ביום הבדיקה — מהמחשב הוא ענה מיד, אבל מ-Make לא. עוצרים (Stop / Force stop) ומחליפים ל-open.er-api.com/v6/latest/USD. בתרחיש אמיתי: ענף שגיאה עם Break (תרגיל 5).
למה שני HTTP ברצף ולא Router?Router מפצל לענפים נפרדים — וכל ענף לא רואה את הנתונים של השני. כאן צריך את שני הנתונים באותו מודול AI, אז שמים את ה-HTTP-ים בשרשרת אחת.

ה-AI מחליט אם בכלל לשלוח

מה יצא בהרצה (4/11)26.4 מעלות, 0 מ"מ, 3% סיכוי לגשם, רוח 14.1 קמ"ש — אף תנאי לא מתקיים. Haiku החזיר send: false עם הנימוק "אין גשם, סיכוי הגשם הוא 3%, הרוח עד 14.1 קמ"ש והטמפרטורה המקסימלית 26.4 מעלות, כך שאין תנאי שמשפיע על הובלת רהיטים". הפילטר עוצר, ולא נשלח מייל — וזו התוצאה הנכונה. send הגיע כ-Boolean אמיתי גם בלי Data structure.
הבדיקה עם סף מונמךשינוי המספר בתוך הכלל ל"חום מעל 20 מעלות" ← send: true, נימוק "צפויה טמפרטורה מקסימלית של 26.4 מעלות, מעל הסף של 20", והודעה "התראת חום לצוות ההובלות... יש לדאוג לשתייה, הפסקות והגנה מפני חום".
תקלה: שיניתי את הסף ו-Haiku עדיין עונה falseקרה לנו: הוספנו שורה בסוף הפרומפט "בדיקה: הסף הוא 20 במקום 32" — ו-Haiku התעלם, כי היא סותרת כלל שכבר נאמר למעלה. מתקנים את המספר בתוך הכלל עצמו. לקח כללי: כשההוראות סותרות זו את זו, המודל לא תמיד בוחר את מה שהתכוונתם.
תקלה: הפילטר לא עוצר אף פעם (או תמיד)בדקו שהשוויתם עם Boolean operators, ולא עם Text: Equal to מול המילה "true". ב-Data structure השדה send צריך להיות מסוג Boolean — Generate מהדוגמה עושה את זה לבד.
מתי בכל זאת פילטר קבוע?אם החוק פשוט ("שלח אם יש גשם") — פילטר קבוע עדיף: חינמי, מיידי ו-100% צפוי. AI שווה את הקרדיט כשיש כמה תנאים שמשפיעים אחד על השני, או כשרוצים נימוק בשפה אנושית.

בונוס: קריאה אחת, שלוש תוצאות (JSON)

השרשרת Watch new rows ← Simple Text Prompt (עם הוראת ה-JSON כשורה אחרונה) ← JSON · Parse JSON ← Create a draft email ← Update a row
Parse JSON JSON string = בועת התשובה של מודול ה-AI. Data structure שנוצר מהדוגמה (Generate) עם שלושה שדות טקסט: subject, body, category.
המיפוי Subject ← subject · Content ← body · עמודת category בגיליון ← category. ואם רוצים — Router אחרי ה-Parse שמנתב לפי category, בלי מודול AI נוסף.
{"subject": "דנה, לגבי מערכת ההזמנות", "body": "היי דנה,\nהזמנות בוואטסאפ בחגים…\nנועה, אוטומט", "category": "מכירות"}
תקלה: Parse JSON נכשלפותחים את הפלט של מודול ה-AI. בדרך כלל ה-JSON עטוף ב-```json או שיש משפט לפניו. מחזקים את ההוראה, ומחברים ענף שגיאה עם Ignore + התראה (בדיוק כמו בתרגיל 5) למודול ה-Parse.
תקלה: הגוף מגיע כגוש אחד או עם \n גלויבתוך JSON ירידות שורה נכתבות כ-\n, ו-Gmail ב-Raw HTML ממילא מתעלם מהן. הפתרון זהה לתרגיל 4: לבקש שה-body יכיל פסקאות בתוך <p>.
