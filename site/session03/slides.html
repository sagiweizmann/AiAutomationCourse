שלוש מילים ממפגש 2

API, JSON, GET — בחצי משפט כל אחד

🔌 API
"שקע" שדרכו מערכת אחת מבקשת מידע ממערכת אחרת. מזג האוויר, שער מטבע, CRM.
🔤 JSON
הפורמט של התשובה: מפתחות וערכים ב-{ }. מגיעים לערך לפי הנתיב שלו.
📥 GET
הבקשה שאומרת "תן לי מידע". בלי לשנות כלום בצד השני.
היום נראה את זה חיMake ישלח בקשת GET ל-API של מזג האוויר, יקבל JSON, ואנחנו נבחר ממנו ערכים לפי הנתיב — בדיוק כמו ב-Hoppscotch, רק שעכשיו זה קורה לבד.
  • אם הכיתה מהוססת על JSON — פתחו שוב את ה-Hoppscotch ממפגש 2 לרגע. זה מחבר.

שני סוגי טריגר

מה מתחיל את התרחיש?

⏰ שעון (Schedule)
  • רץ בזמן קבוע: כל יום ב-07:00, כל 15 דקות
  • טוב ל: דוחות, סנכרון, "תחזית הבוקר"
  • המודול הראשון פשוט רץ לפי התזמון
⚡ אירוע (Watch)
  • רץ כשמשהו קורה: שורה חדשה, מייל נכנס
  • טוב ל: תגובה מיידית לליד, להזמנה
  • Make "צופה" ומריץ רק כשיש חדש

  • זו הבחנה שחוזרת בכל הקורס. ודאו שהיא ברורה לפני הבנייה.
שני מושגים שמבלבלים בהתחלה

חיבור (Connection) ומיפוי (Mapping)

🔑 חיבור
ההרשאה של Make לגשת לחשבון שלכם (Gmail, Sheets). מחברים פעם אחת, ואז כל המודולים של אותה אפליקציה משתמשים בו.
🧩 מיפוי
לקחת שדה שיצא ממודול אחד ולהכניס אותו לתוך מודול אחר — ה"בועות" הסגולות. למשל: הטמפרטורה מה-HTTP ← לתוך גוף המייל.
הטעות הנפוצה ביותרלהקליד {{current.temperature_2m}} ביד כטקסט. זה לא עובד! צריך לבחור את השדה מהרשימה, כדי ש-Make יכניס את הערך האמיתי.
  • המיפוי הוא ה"קסם" של Make. הדגימו חי: שדה שנבחר נראה כבועה צבעונית, לא כטקסט.
  • החיבור — הרגיעו: עושים פעם אחת, לא בכל מודול.
כך זה נראה ב-Make

מיפוי: בוחרים שדה מהרשימה — לא מקלידים

מודול 1 · מושכים מידע

HTTP → Make a request

מה ממלאים
  • Authentication type = No authentication
  • URL = הכתובת של מזג האוויר (למטה)
  • Method = GET
  • Parse response = Yes ← קריטי!
למה Parse = Yes
בלי זה, Make מקבל את ה-JSON כטקסט אחד גדול. עם Yes — הוא הופך אותו לשדות שאפשר לבחור ולמפות.

כלי 1 · פילטר

לשלוח רק כשחשוב — פילטר על החוט

איך מוסיפים
  • לוחצים על החוט שבין HTTP למייל
  • אייקון מפתח → Set up a filter
  • תנאי: precipitation Greater than 0
מה קורה עכשיו
אין משקעים → precipitation = 0 → התנאי לא מתקיים → המייל לא נשלח. יש גשם → ממשיך רגיל.
אוטומציה טובה לא מציפהצוות המשלוחים מקבל מייל רק כשיש משהו לעשות איתו — גשם. שאר הימים שקטים. זה ההבדל בין עוזר למטרד.
  • לבדיקה: שנו זמנית את הערך ל-1− כדי לראות שהמייל כן יוצא. אחר כך מחזירים ל-0.

הפער

Make מזיז — אבל מי "חושב"?

✅ Make עושה מצוין
  • להעביר נתונים בין אפליקציות
  • לתזמן, לסנן, לתעד
  • תנאים פשוטים: גדול/קטן/שווה
🤖 כאן צריך את Claude
  • לנסח תשובה אישית ללקוח
  • לסווג פנייה לפי נושא ודחיפות
  • לסכם טקסט חופשי, לחלץ JSON
  • להחליט לפי שיקול, לא רק לפי מספר
הצעד הבאבתרחיש הלידים — במקום רק להתריע, Claude ינסח טיוטת תשובה ללקוח. Make ישלח ל-Claude את פרטי הליד, ויקבל בחזרה טקסט. בדיוק כמו קריאת API — רק של Claude.
  • חברו לתרגיל 6: "סמנתם שלב שבו צריך ראש? זה השלב שבו Claude ייכנס."
מה זה בכלל

Claude API — Claude בלי הצ'אט

💬 claude.ai (מה שהכרנו)
  • אתם מדברים עם Claude בחלון צ'אט
  • אדם שולח, אדם קורא
  • כלול בחשבון, לפי מנוי
🔌 Claude API (החדש)
  • Make שולח ל-Claude, Make מקבל תשובה
  • בלי אדם באמצע — בתוך אוטומציה
  • משלמים לפי שימוש (טוקנים), עם מפתח API
אותו Claude, כניסה אחרתה-API הוא פשוט דלת שדרכה תוכנה (Make) מדברת עם Claude, במקום אדם. צריך לזה חשבון נפרד — פלטפורמת ה-API — ומפתח API, שנשמור בסוד.
  • ההבחנה הזו מבלבלת רבים: "כבר יש לי Claude, למה עוד חשבון?" — כי זה ערוץ אחר, לתוכנה.
  • מפתח API = סיסמה שמחייבת את החשבון. לא משתפים, לא מעלים לגיט.
כמה זה עולה

משלמים לפי שימוש — טוקנים

💬 claude.ai
מנוי חודשי קבוע. משלמים אותו דבר בין אם שלחתם הודעה אחת או מאה.
🔌 Claude API
משלמים רק על מה שהשתמשתם. כל קריאה עולה לפי אורך הטקסט שנכנס ויוצא — נמדד ב"טוקנים" (בערך 3/4 מילה כל טוקן).
בפועל — זול לרוב השימושיםניסוח מייל קצר עולה שברירי אגורות. אבל כי זה לפי שימוש — חשוב להבין את התמחור לפני שמחברים אוטומציה שרצה אלפי פעמים. נעשה את זה ביחד בשיעור הבא.
  • אל תיכנסו למספרים מדויקים — העיקרון: מנוי קבוע מול תשלום-לפי-שימוש.
  • הרגיעו: ללמידה ולתרגול העלות זניחה. החשש האמיתי הוא אוטומציה שרצה בלולאה בלי בקרה.

מה להכין לשיעור הבא

✅ כבר יש לכם

  • חשוב: לא לשלוח אותם להירשם לבד עם כרטיס אשראי. עושים ביחד, מבינים את התמחור קודם.
