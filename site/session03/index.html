מתכננים את התרחיש על הנייר

⏱ 8 דקותקלבכיתה

לפני שנוגעים ב-Make — לתרגם את התהליך לשפה של אוטומציה: טריגר, צעדים ופעולה. בדיוק מה שאפיינו במפגש 2.

כל אוטומציה היא טריגר (מה מתחיל אותה) ← צעדים (מה קורה באמצע) ← פעולה (התוצאה). מלאו את הטבלה לתרחיש "תחזית הבוקר":

חלקמה כותבים
טריגר — מתי רץ?_________ (רמז: לא אירוע חיצוני, אלא שעון)
מקור נתונים — מאיפה המידע?_________ (רמז: אותו API ממפגש 2)
עיבוד — מה לוקחים מהתשובה?_________ (אילו שדות מתוך ה-JSON?)
פעולה — מה התוצאה?_________ (לאן זה נשלח?)
תזכורת ממפגש 2 — הכתובת של מזג האוויר (מצב נוכחי, אשדוד) https://api.open-meteo.com/v1/forecast?latitude=31.79213&longitude=34.64966&current=temperature_2m,precipitation,weather_code&timezone=Asia%2FJerusalem
רמז

טריגר = תזמון (כל יום ב-07:00). מקור = בקשת GET ל-open-meteo. עיבוד = לקרוא את current.temperature_2m ואת current.precipitation מה-JSON. פעולה = מייל + שורה בגיליון.

איך יודעים שעשיתם טוב

  • הטריגר הוא תזמון (שעון), לא אירוע חיצוני
  • זיהיתי אילו שדות מתוך ה-JSON אני צריך (טמפרטורה ומשקעים)
  • יש לי ברור מה הפעולה הסופית — לאן התחזית נשלחת

בונים: Schedule → HTTP → שליחה

⏱ 20 דקותבינוניבכיתה

לבנות את התרחיש הראשון שעובד מקצה לקצה: כל בוקר מושך את מזג האוויר ושולח אותו. בלי Claude.

1. תרחיש חדש + מודול ה-HTTP

  1. ב-Scenarios לוחצים Create a new scenario
  2. לוחצים על העיגול הגדול עם ה-+, מחפשים HTTP ובוחרים Make a request
  3. ממלאים: Authentication type = No authentication, URL = הכתובת של מזג האוויר (למטה), Method = GET
  4. חשוב: מגלגלים למטה ל-Parse response ובוחרים Yes — כך Make הופך את ה-JSON לשדות שאפשר לבחור
https://api.open-meteo.com/v1/forecast?latitude=31.79213&longitude=34.64966¤t=temperature_2m,precipitation,weather_code&timezone=Asia/Jerusalem
  1. לוחצים Run once (למטה משמאל), פותחים את ה-Output ומרחיבים את current: צריך לראות current.temperature_2m עם מספר אמיתי

2. הפעולה: שולחים מייל

  1. לוחצים על ה-+ ליד מודול ה-HTTP ומחפשים Gmail → Send an email
  2. בפעם הראשונה לוחצים Create a connection ומתחברים לחשבון Google (אישור הרשאות)
  3. ממלאים: To = המייל שלכם · Subject = "תחזית הבוקר — אשדוד"
  4. ב-Content כותבים טקסט, ובתוכו בוחרים מהרשימה את השדות מה-HTTP (ה"בועות" הסגולות):
בוקר טוב! מזג האוויר באשדוד עכשיו:
טמפרטורה: {{current.temperature_2m}} מעלות
משקעים: {{current.precipitation}} מ"מ
איך ממפים שדהלא מקלידים {{current.temperature_2m}} ביד — לוחצים בתוך שדה התוכן, ומהחלונית שנפתחת בוחרים את השדה מתוך מודול ה-HTTP. Make מכניס את ה"בועה" לבד.

3. הפעולה הנוספת: כותבים לגיליון

  1. פותחים ב-Google Sheets גיליון חדש עם כותרות בשורה הראשונה: date, temp, rain
  2. ב-Make מוסיפים מודול Google Sheets → Add a row, בוחרים את הקובץ והגיליון
  3. ממפים: date ← {{now}} · temp ← current.temperature_2m · rain ← current.precipitation

4. תזמון + הפעלה

  1. לוחצים על שעון התזמון (מתחת למודול הראשון) ובוחרים Every day בשעה 07:00
  2. לוחצים Run once לבדיקה אחרונה — בודקים שהגיע מייל ושנוספה שורה בגיליון
  3. מדליקים את המתג ON (למטה משמאל) כדי שהתרחיש ירוץ לבד
משהו נתקע?

מודול ה-HTTP אדום? בדקו שה-URL הודבק במלואו ושה-Method הוא GET. לא רואים את שדות מזג האוויר במייל? חזרו ל-HTTP וּודאו ש-Parse response = Yes, ואז הריצו Run once שוב כדי ש-Make "ילמד" את השדות.

איך יודעים שעשיתם טוב

  • מודול ה-HTTP מחזיר JSON עם טמפרטורה אמיתית
  • קיבלתי מייל עם הטמפרטורה והמשקעים האמיתיים (לא {{...}} גולמי)
  • נוספה שורה בגיליון עם תאריך, טמפרטורה ומשקעים
  • התרחיש מתוזמן לכל בוקר ומצבו ON
3

מוסיפים תנאי: שולחים רק כשיורד גשם

⏱ 10 דקותבינוניבכיתה

אוטומציה טובה לא מציפה. נוסיף פילטר שמעביר הלאה רק כשיש משקעים — בדיוק מה שמעניין את צוות המשלוחים.

  1. בתרחיש מתרגיל 2, לוחצים על הקו (ה"חוט") שבין מודול ה-HTTP למודול המייל
  2. לוחצים על אייקון מפתח הברגים Set up a filter
  3. נותנים שם לפילטר: "רק אם יש גשם"
  4. בתנאי: בשדה הראשון בוחרים current.precipitation, בוחרים Greater than, ובערך כותבים 0
  5. לוחצים Run once — אם אין גשם עכשיו, המייל לא יישלח (והקו מראה שהחבילה נעצרה בפילטר)
איך בודקים שזה באמת עובדכדי לוודא שהמייל כן יוצא כשצריך, שנו זמנית את הערך בפילטר ל--1 (כל מספר גדול מ-1−). אם עכשיו המייל יוצא, הפילטר תקין. אחר כך החזירו ל-0.
רמז: מתי הפילטר "חוסם"?

פילטר מעביר הלאה רק חבילות שעומדות בתנאי. precipitation > 0 אומר: המשך רק אם יש אפילו טיפה. אין משקעים → precipitation = 0 → התנאי לא מתקיים → המודול הבא לא רץ.

איך יודעים שעשיתם טוב

  • יש פילטר על הקו שבין ה-HTTP למייל, עם התנאי precipitation > 0
  • כשאין משקעים, המייל לא נשלח (ראיתי שהחבילה נעצרה בפילטר)
  • בדקתי שהמייל כן יוצא כשהתנאי מתקיים (על ידי שינוי זמני של הערך)

תרחיש שני: שורה חדשה בגיליון → התראה

⏱ 15 דקותבינוניבכיתה

להכיר טריגר מסוג אחר: לא שעון, אלא אירוע. כשנכנסת שורה חדשה לגיליון, Make מגיב מיד.

תרחיש אמיתי ל"בית ועיצוב": יש גיליון "לידים" שבו מזכירה מוסיפה כל פנייה חדשה. רוצים שבכל פנייה חדשה תצא התראה אוטומטית.

  1. מכינים גיליון לידים עם כותרות: name, product, phone
  2. תרחיש חדש → מודול ראשון: Google Sheets → Watch rows (זה הטריגר)
  3. בוחרים את הקובץ, הגיליון, ו-Row with headers = Yes. שומרים
  4. מוסיפים מודול שני — Gmail → Send an email (או Email מובנה) — ובתוכן ממפים את name, product ו-phone מהשורה:
ליד חדש נכנס! 🎉
שם: {{name}}
מוצר: {{product}}
טלפון: {{phone}}
  1. לוחצים Run once, ואז מוסיפים שורה חדשה בגיליון ורואים שההתראה יוצאת
  2. מתזמנים את הטריגר (למשל כל 15 דקות) ומדליקים ON
רמז: למה זה שונה מתרגיל 2?

בתרגיל 2 הטריגר היה שעון (רץ בזמן קבוע). כאן הטריגר הוא אירוע — Make "צופה" בגיליון ומריץ את התרחיש רק כשמשהו משתנה. Watch rows זוכר את השורה האחרונה שעיבד, כך שלא שולח פעמיים.

איך יודעים שעשיתם טוב

  • המודול הראשון הוא Watch rows (טריגר של אירוע, לא שעון)
  • הוספתי שורה חדשה וקיבלתי התראה עם השם, המוצר והטלפון
  • אני יכול להסביר במשפט את ההבדל בין טריגר של שעון לטריגר של אירוע

דיבוג: התרחיש השבור

⏱ 10 דקותמאתגרבכיתה

אוטומציה נשברת — זה חלק מהעבודה. נלמד לקרוא את ההיסטוריה ולמצוא איפה זה נתקע.

לפניכם שלוש תקלות נפוצות. לכל אחת, כתבו מה הסימן שתראו ב-Make, ומה התיקון:

תקלה א'בניתם את תרחיש מזג האוויר, אבל במייל מופיע הטקסט {{current.temperature_2m}} במקום מספר.
תקלה ב'מודול ה-HTTP צבוע באדום אחרי Run once, וההרצה נעצרת עליו. בהיסטוריה כתוב URL is required.
תקלה ג'תרחיש "שורה חדשה → התראה" שולח התראה על אותו ליד שוב ושוב בכל הרצה.
איפה מחפשיםכל הרצה נשמרת ב-History של התרחיש. לוחצים על הרצה, ואז על כל מודול — רואים בדיוק מה נכנס אליו ומה יצא ממנו. שם מתגלות כמעט כל התקלות.
רמז לכל תקלה

א' — השדה הוקלד כטקסט ולא נבחר כ"בועה", או ש-Parse response היה No. ב' — ה-URL ריק או לא נשמר. ג' — הטריגר אולי Search rows במקום Watch rows, או שהמיפוי של "השורה האחרונה שעובדה" אופס.

איך יודעים שעשיתם טוב

  • לכל תקלה כתבתי את הסימן ואת התיקון
  • פתחתי את ה-History של תרחיש אמיתי שלי ובדקתי קלט/פלט של מודול
  • אני יודע להסביר למה תקלה א' נותנת טקסט גולמי במקום מספר
