פתרונות: האוטומציה הראשונה ב-Make

תשובות מלאות ותשובות לדוגמה לכל ששת התרגילים. חלק מהתרגילים (תכנון, מיפוי תהליך) פתוחים — שם זו דוגמה טובה, לא "התשובה היחידה". ערכי מזג אוויר חיים משתנים כל הזמן, אז מה שחשוב הוא הנתיב והמבנה, לא המספר המדויק.

1

מתכננים את התרחיש על הנייר

תרגיל פתוח — זו התשובה הנכונה לתרחיש "תחזית הבוקר".

חלקהתשובה
טריגרשעון (Schedule) — כל יום ב-07:00. לא אירוע חיצוני, אלא תזמון קבוע.
מקור נתוניםבקשת GET ל-API של open-meteo (אשדוד) — אותו API ממפגש 2.
עיבודמתוך ה-JSON לוקחים את current.temperature_2m ואת current.precipitation.
פעולהשליחת מייל (Gmail) + הוספת שורה לגיליון (Google Sheets).
למה שעון ולא אירוע?אין כאן "משהו שקורה" שצריך להגיב אליו — פשוט רוצים מידע בזמן קבוע כל בוקר. זה בדיוק המקרה של טריגר שעון.
2

בונים: Schedule → HTTP → שליחה

שרשרת המודולים המלאה, מודול-מודול:

מודול 1 · HTTP → Make a request
  • URL = הכתובת של מזג האוויר (למטה)
  • Method = GET
  • Parse response = Yes (קריטי — בלי זה אין שדות למפות)
https://api.open-meteo.com/v1/forecast?latitude=31.79213&longitude=34.64966¤t=temperature_2m,precipitation,weather_code&timezone=Asia/Jerusalem
מודול 2 · Gmail → Send an email
  • חיבור ל-Google (פעם אחת) · To = המייל שלכם · Subject = "תחזית הבוקר — אשדוד"
  • בתוכן בוחרים את השדות מה-HTTP (לא מקלידים):
טמפרטורה: {{current.temperature_2m}} מעלות
משקעים: {{current.precipitation}} מ"מ
מודול 3 · Google Sheets → Add a row

גיליון עם כותרות date | temp | rain, ומיפוי: date ← {{now}} · temp ← current.temperature_2m · rain ← current.precipitation.

תזמון והפעלה

שעון → Every day → 07:00. Run once לבדיקה, ואז מתג ON.

בדיקהאם במייל מופיע מספר אמיתי (לא {{...}}) ובגיליון נוספה שורה — התרחיש עובד. הערכים אצל כל אחד שונים כי זה מזג אוויר חי.
3

מוסיפים תנאי: שולחים רק כשיורד גשם

הפילטר

לוחצים על החוט בין ה-HTTP למייל → אייקון מפתח → Set up a filter. התנאי:

current.precipitation   Greater than   0
איך בודקים שהוא עובד

אין משקעים עכשיו → precipitation = 0 → התנאי לא מתקיים → המייל לא יוצא (רואים שהחבילה נעצרה בפילטר). לבדיקה חיובית: שנו זמנית את הערך ל--1, הריצו, וראו שהמייל כן יוצא. אחר כך החזירו ל-0.

הרעיוןפילטר מעביר הלאה רק מה שעומד בתנאי. כך צוות המשלוחים מקבל מייל רק בימי גשם — לא כל בוקר.
4

תרחיש שני: שורה חדשה בגיליון → התראה

שרשרת המודולים
  • מודול 1 (טריגר): Google Sheets → Watch rows — בוחרים את גיליון הלידים, Row with headers = Yes
  • מודול 2: Gmail → Send an email, וממפים name, product, phone מהשורה
  • מתזמנים את הטריגר (למשל כל 15 דקות) ומדליקים ON
ההבדל מתרגיל 2

בתרגיל 2 הטריגר הוא שעון — רץ בזמן קבוע. כאן הטריגר הוא אירוע — Make "צופה" בגיליון ומריץ רק כשנכנסת שורה חדשה. Watch rows זוכר את השורה האחרונה שעיבד, כדי לא לשלוח התראה כפולה על אותו ליד.

5

דיבוג: התרחיש השבור

תקלה א' — טקסט {{current.temperature_2m}} במקום מספר

סימן: המייל מכיל את שם השדה כטקסט. תיקון: השדה הוקלד ביד במקום להיבחר — מוחקים, לוחצים בשדה התוכן ובוחרים את השדה מהרשימה. ואם זה לא עוזר — Parse response היה No: מעבירים ל-Yes, מריצים Run once שוב כדי ש-Make "ילמד" את השדות, וממפים מחדש.

תקלה ב' — מודול אדום, URL is required

סימן: ההרצה נעצרת על מודול ה-HTTP. תיקון: ה-URL ריק או לא נשמר — מדביקים את הכתובת המלאה בשדה URL, שומרים את המודול (OK), ומריצים שוב.

תקלה ג' — שולח התראה על אותו ליד שוב ושוב

סימן: בכל הרצה יוצאת התראה על שורות ישנות. תיקון: כנראה נבחר Search rows (שמחזיר הכול בכל פעם) במקום Watch rows (שזוכר איפה עצר). מחליפים ל-Watch rows, וב-Choose where to start בוחרים "מעכשיו והלאה".
