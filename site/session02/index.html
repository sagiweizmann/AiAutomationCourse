אפיון תהליך ההחזרות

⏱ כ-25 דקותבזוגותבכיתה

לקחת תהליך אמיתי (החזרת מוצר), למפות אותו כמו שהוא קורה באמת, ולהחליט מה כדאי לאטמט.

עובדים בזוגות. אחד משחק נציג שירות שמטפל בהחזרות, השני מראיין. הטריק החשוב: בקשו לעבור על המקרה האמיתי האחרון שטופל, לא על "איך זה בדרך כלל".

1. ראיון — 8 כיווני חקירה

8 השאלות התחלה: מה מתחיל את התהליך? מאיפה מגיעה הבקשה? שלבים: תעבור/י איתי צעד אחרי צעד על המקרה האחרון. מערכות: באילו מערכות, קבצים או אתרים משתמשים בכל שלב? זמנים: כמה זמן כל שלב? כמה פעמים בחודש? החלטות: איפה צריך להחליט? לפי אילו כללים? חריגים: מה קורה כשמשהו לא מסתדר? כמה זה נפוץ? כאבים: מה הכי מעצבן? איפה יש טעויות? הצלחה: איך נראה תהליך מושלם מבחינתך?

לא חייבים את כולן. החשובות: שלבים (מקרה אמיתי) וכאבים (שם מסתתרת ההזדמנות). רשמו את שלבי ה-As-Is בנקודות.

2. מיפוי — תרשים זרימה עם Claude

הדביקו ל-Claude את שלבי ה-As-Is ובקשו תרשים Mermaid:

אלה שלבי תהליך ההחזרות אצלנו (As-Is):
[הדביקו כאן את השלבים שרשמתם]

צייר לי תרשים זרימה ב-Mermaid (flowchart) שמתאר אותם.
סמן בצורת מעוין כל נקודה שבה צריך להחליט החלטה.
בסוף, ציין במשפט אחד איפה לדעתך צוואר הבקבוק.
איפה רואים את התרשיםClaude מצייר את ה-Mermaid ישירות בצ'אט. אם לא — בקשו "הצג את זה כתרשים", או הדביקו את הקוד ב-mermaid.live.

3. ניקוד — מה לאטמט קודם

דרגו כל שלב בתהליך לפי שני צירים, מ-1 (נמוך) עד 5 (גבוה):

שלב בתהליךערך (כמה כואב / חוזר)קלות (כמה פשוט לאטמט)עדיפות
לדוגמה: בדיקת זכאות להחזר במסמך45גבוהה ⭐

שלב עם ערך גבוה + קלות גבוהה = הזדמנות הזהב. מתחילים ממנו.

4. ROI — כמה זה שווה

לשלב שבחרתם, חשבו חיסכון חודשי: פעמים בחודש × דקות לשלב × (עלות שעה ÷ 60). לדוגמה: 120 החזרות × 6 דקות × (60 ₪ ÷ 60) = 720 ₪ לחודש.

התוצרמסמך אפיון של עמוד אחד לתהליך ההחזרות: שלבי As-Is, תרשים To-Be (Mermaid), טבלת ניקוד, וחישוב ROI לשלב אחד.

איך יודעים שעשיתם טוב

  • מיפיתי מקרה אמיתי אחרון, ולא תיאור כללי של "איך זה עובד"
  • יש תרשים Mermaid עם לפחות נקודת החלטה אחת (מעוין)
  • סימנתי שלב אחד בעדיפות גבוהה והסברתי למה
  • חישבתי ROI חודשי לאותו שלב במספרים

בקשות API אמיתיות ב-Hoppscotch

⏱ כ-12 דקותכלי אמיתיבכיתה

לשלוח בקשות API אמיתיות בלי לכתוב שורת קוד, ולראות תשובה וקוד סטטוס.

פותחים את הכלי

  1. נכנסים ל-hoppscotch.io (כלי חינמי בדפדפן. אפשר גם Postman)
  2. בוחרים שיטה (GET / POST), מדביקים כתובת בשורת הכתובת, ולוחצים Send
  3. התשובה וקוד הסטטוס מופיעים בחלק התחתון
שגיאת רשת (CORS)?אם מופיעה Network Error, החליפו את ה-Interceptor (בהגדרות, בפינה) מ-Browser ל-Proxy, ושלחו שוב.

הבקשות

1 · תחזית שבועית באשדוד, ישראל (GET)GET https://api.open-meteo.com/v1/forecast?latitude=31.79213&longitude=34.64966&daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max&timezone=Asia%2FJerusalem&forecast_days=7 → מצפים לקוד 200. שבעת ימי התחזית נמצאים במערכים: daily.time, daily.temperature_2m_max, daily.temperature_2m_min, daily.precipitation_probability_max ו-daily.weather_code
2 · שער הדולר לשקל (GET)GET https://api.frankfurter.app/latest?from=USD&to=ILS → קוד 200. השדה: rates.ILS
3 · יצירת רשומה (POST) — שימו לב לקוד 201POST https://jsonplaceholder.typicode.com/posts לשונית Body → raw / application/json: { "title": "בדיקה", "userId": 1 }
בונוס · איך השרת רואה את הבקשה שלכם (GET)GET https://httpbin.org/get
התוצרצילום מסך של התחזית השבועית באשדוד (קוד 200) ושל ה-POST (קוד 201), וזיהוי התאריך, טמפרטורת המקסימום והמינימום וסיכוי הגשם לכל יום.

איך יודעים שעשיתם טוב

  • קיבלתי קוד 200 על בקשת ה-GET ו-201 על ה-POST
  • אני יודע להתאים בין התאריך, טמפרטורת המקסימום והמינימום וסיכוי הגשם לפי אותו מיקום במערכי daily
  • הבנתי את ההבדל בין GET (קוראים נתונים) ל-POST (יוצרים רשומה)

סבב API-ים חינמיים

⏱ כ-12 דקותכיף + נתיבבכיתה

לתרגל קריאת ערך מתוך JSON לפי נתיב, על כמה API-ים אמיתיים וחינמיים.

הדביקו כל כתובת ב-Hoppscotch (שיטה GET), לחצו Send, ומצאו בתשובה את הערך המבוקש לפי הנתיב.

1 · תחזית שבועית באשדודapi.open-meteo.com/v1/forecast?latitude=31.79213&longitude=34.64966&daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max&timezone=Asia%2FJerusalem&forecast_days=7 → מה הטמפרטורה הגבוהה והנמוכה ומה סיכוי הגשם בכל יום? (נתיבים: daily.temperature_2m_max, daily.temperature_2m_min, daily.precipitation_probability_max)
2 · שער דולר-שקלapi.frankfurter.app/latest?from=USD&to=ILS → כמה שקלים שווה דולר? (נתיב: rates.ILS)
3 · מחיר ביטקוין בשקליםapi.coingecko.com/api/v3/simple/price?ids=bitcoin&vs_currencies=ils → מה המחיר? (נתיב: bitcoin.ils)
4 · ניחוש גיל משםapi.agify.io/?name=noa → איזה גיל ניחש המודל? (נתיב: age)
התוצרצילום מסך של אחת התשובות, עם סימון הנתיב לערך שמצאתם.

איך יודעים שעשיתם טוב

  • מצאתי את הערך הנכון בכל אחת מהתשובות
  • אני מבין שהנתיב (למשל rates.ILS) הוא בדיוק מה שנשלוף ב-Make מהתשובה

Claude מחלץ נתונים ל-JSON

⏱ כ-15 דקותעם Claudeבכיתה

לכתוב פרומפט אחד שמחזיר JSON עקבי מכל פנייה. בדיוק מה ש-Make ישלח דרך API.

  1. פתחו את Claude בצ'אט, הדביקו את הפרומפט ושלחו
  2. אחר כך החליפו את הפנייה בשתי פניות משלכם, אחת מהן עם פרט חסר
אתה מחלץ נתונים מפניות לקוחות של "בית ועיצוב".
החזר JSON בלבד (בלי טקסט מסביב) עם השדות:
customer_name, order_id, topic (אחד מ: delivery / defect / refund / other), urgency (low / high).
אם שדה לא מופיע בפנייה, החזר null.

הפנייה:
"שלום, מדברת רונית שגב. ההזמנה שלי (50912) הייתה אמורה להגיע אתמול ולא הגיעה, ואני צריכה אותה דחוף."
התוצרצילום מסך של ה-JSON ש-Claude החזיר ל-3 פניות שונות, אחת מהן עם שדה חסר (שחזר null).

איך יודעים שעשיתם טוב

  • הפלט הוא JSON בלבד: בלי "הנה התשובה:" ובלי ``` מסביב
  • אותם ארבעה שדות חוזרים בכל שלוש הפניות
  • בפנייה בלי מספר הזמנה, order_id קיבל null ולא ערך שהומצא
  • topic ו-urgency רק מתוך הרשימה הסגורה

Claude בונה את תוכנית האוטומציה

⏱ כ-15 דקותעם Claudeבכיתה

להשתמש ב-Claude כשותף לתכנון: לתת לו את ה-As-Is ולקבל תוכנית אוטומציה ל-Make.

קחו את התהליך שמיפיתם בתרגיל 1, ובקשו מ-Claude לתרגם אותו לתוכנית אוטומציה.

זה תהליך As-Is שמיפיתי (הדביקו כאן את השלבים שלכם).

אני רוצה להפוך אותו לאוטומציה ב-Make. תכנן לי:
1. מה הטריגר (Webhook / Polling)?
2. אילו מודולים נדרשים ובאיזה סדר?
3. איפה Claude נכנס, ומה הוא מקבל ומחזיר (JSON)?
4. היכן חייבת להיות נקודת אישור של אדם?
5. אילו קודי תשובה צריך לטפל בהם (401 / 404 / 429)?

החזר טבלה קצרה של המודולים.
זכרוClaude מציע, האדם מחליט. אל תקבלו תוכנית בעיניים עצומות — קראו אותה וחשבו מה הייתם משנים.
התוצרתוכנית אוטומציה מ-Claude לתהליך שלכם, עם הערה אחת שלכם: מה הייתם משנים בה.

איך יודעים שעשיתם טוב

  • יש טבלת מודולים עם טריגר ברור (Webhook או Polling)
  • יש לפחות נקודת אישור אנושית אחת בתוכנית
  • התוכנית מציינת איפה Claude נכנס ומה הוא מחזיר (JSON)
  • כתבתי הערה אחת משלי: מה הייתי משנה
