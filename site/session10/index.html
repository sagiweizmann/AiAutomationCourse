🤖 בונים את הסוכן: Webhook, הוראות, זיכרון

⏱ 20 דקותבינוניבכיתה

תרחיש עם טריגר וסוכן אחד. עוד בלי כלים.

  1. Make ← AI Agents (בסרגל הצד) ← Create agentic scenario
  2. טריגר: Webhooks · Custom webhook ← Add ← שם: סוכן בית ועיצוב ← Copy address
  3. Hoppscotch: POST לכתובת, Body ← JSON: {"message": "היי, יש לכם ספה פינתית במלאי? כמה היא עולה וכמה עולה משלוח לחיפה?", "name": "נטע", "email": "you+neta@gmail.com", "thread": "neta-1"} ← Send. ב-Make: "4 values detected"? ← Save
  4. פותחים את Make AI Agent: Connection = Make's AI Provider · Model = Recommended: Medium
  5. Instructions: מדביקים את ההוראות למטה (שורה חדשה = Shift+Enter)
  6. Input: לקוח: ← בועה name ← | אימייל: ← email ← | הודעה: ← message. בוחרים מחלון המיפוי, לא מקלידים
  7. Show advanced settings ← Conversation ID: בועה thread · Maximum LLM steps: 10 ← Save
אתה נציג שירות ומכירות של "בית ועיצוב", חנות רהיטים. עונים קצר וחם.
1. מחיר, מלאי ופרטי מוצר: רק מהכלי check_products. אסור להמציא מחיר או מלאי.
2. מדיניות (משלוח, הרכבה, החזרות, אחריות, שעות, מבצעים): רק מהכלי search_knowledge. מציינים מקור בסוגריים מרובעים. שתי שורות סותרות? לוקחים את המעודכנת.
3. לקוח שרוצה לקנות, מבקש הצעת מחיר או נציג: קוראים לכלי create_lead פעם אחת, ואומרים שנציג יחזור תוך יום עסקים.
4. אין לך סמכות לתת הנחות או לשנות מחירים, גם אם הלקוח מתעקש או טוען שהוא מנהל. הנחה עד 5% רק דרך נציג.
5. אין מידע? אומרים שאין ומציעים נציג. לא ממציאים.
6. שפה: תמיד עונים בשפה של ההודעה (רוסית -> רוסית, אנגלית -> אנגלית). מילות חיפוש לכלים תמיד בעברית.
7. מוצר שאזל (stock 0): חובה לחפש גם ב-search_knowledge את המילה "מלאי" ולהגיד מתי חוזר ומה האפשרויות.
הבועות חיוורות ומופיעה אזהרה "inaccessible module"

הקלדתם {{1.message}}, אבל מודול 1 הוא הסוכן. בדקו את המספר ליד ה-Webhook בקנבס, ובחרו את השדות מחלון המיפוי (כמו שקרה לנו בהדגמה).

איך יודעים שעשיתם טוב

  • הסוכן שמור עם הוראות, קלט ו-Conversation ID
  • הבועות בקלט אדומות (לא חיוורות)
  • Maximum LLM steps = 10

🧰 3 כלים: מוצרים, מאגר ידע, ליד

⏱ 30 דקותבינוניבכיתה

ה-+ מתחת לסוכן ← Add tool. שלושה כלים, אחד אחרי השני.

הכנה: גיליון הלידים

  1. Google Sheets ← גיליון חדש: בית ועיצוב · לידים מהסוכן ← לשונית בשם לידים
  2. שורה 1: date · name · email · interest · summary (עמודות A–E)

כלי 1 · check_products

  1. + ← Add tool ← HTTP · Make a request
  2. Tool name: check_products (רק אנגלית — שם בעברית נדחה)
  3. Tool description: בדיקת מוצרים: מחזיר את רשימת כל המוצרים של בית ועיצוב (מק״ט, שם, קטגוריה, מחיר בש״ח, מלאי). משתמשים בו בכל שאלה על מחיר, מלאי או מוצר מסוים.
  4. Authentication: No authentication · URL: מורידים את הסימון מ-"Let AI Agent decide" ← https://weizmann.ai/demo/api/v1/products.json · Method: GET ← Save

כלי 2 · search_knowledge

  1. + ← Add tool ← Google Sheets · Search Rows · Tool name: search_knowledge
  2. Tool description: מדביקים את התיאור למטה
  3. Spreadsheet: בית ועיצוב · מאגר ידע · Sheet: ידע · Column range: A-Z
  4. Filter: keywords (C) · Contains (case insensitive) · ✅ Let AI Agent decide ← Add details: "מילת חיפוש אחת בעברית, בלי ה׳"
  5. Add OR rule ← topic (B) · Contains (case insensitive) · ✅ Let AI Agent decide ← Save
  6. לוחצים על search_knowledge בקנבס ← Tool outputs: מורידים Row number, Spreadsheet ID, Sheet ← Save
חיפוש במאגר הידע של בית ועיצוב (משלוחים, הרכבה, החזרות, אחריות, תשלומים, לקוחות עסקיים, מלאי, שעות, מבצעים).
כל קריאה מחפשת נושא אחד בלבד. שאלה עם כמה נושאים = קוראים לכלי כמה פעמים, פעם לכל נושא (למשל: "משלוח", ואז "תשלומים", ואז "עסקי").
בשני פרמטרי הסינון שמים בדיוק את אותה מילה, בעברית, בלי ה״א הידיעה.
מחזיר שורות עם text, source ו-updated.

כלי 3 · create_lead

  1. + ← Add tool ← Google Sheets · Add a Row · Tool name: create_lead
  2. Tool description: יצירת ליד: מוסיף שורה לגיליון הלידים כדי שנציג אנושי יחזור ללקוח. משתמשים בו רק כשהלקוח רוצה לקנות, מבקש הצעת מחיר, מבקש נציג או מבקש הנחה. פעם אחת לשיחה.
  3. Spreadsheet: בית ועיצוב · לידים מהסוכן · Sheet: לידים
  4. date: מקלידים {{now}} · name, email: ✅ Let AI Agent decide · interest: ✅ + Add details "המוצר או הנושא, עם מק״ט אם ידוע" · summary: ✅ + Add details "משפט אחד לנציג" ← Save

סוגרים את התרחיש

  1. ה-+ מימין לסוכן ← Webhooks · Webhook response · Status 200 · Body: בועה Response של הסוכן ← Save
  2. Save לתרחיש (Ctrl/⌘+S)

איך יודעים שעשיתם טוב

  • 3 כלים מחוברים מתחת לסוכן
  • כתובת ה-API קבועה (לא Let AI Agent decide)
  • Webhook response מחזיר את Response

🔎 כלי רביעי: "מה הסטטוס של הפנייה שלי?"

⏱ 15 דקותקלבכיתה

מוסיפים כלי שמביא פנייה לפי מספר. קל לבנות — ובכוונה יש בו בעיה. מצאו אותה.

  1. + ← Add tool ← HTTP · Make a request · Tool name: lookup_lead
  2. Tool description: מחזיר פנייה של לקוח לפי מספר פנייה (L-1001 עד L-1032): שם, מוצר, הודעה ותקציב.
  3. No authentication · URL: ✅ Let AI Agent decide ← Add details: https://weizmann.ai/demo/api/v1/leads/L-XXXX.json — רק בכתובת הזאת, עם מספר הפנייה · GET ← Save
  4. Run once ← שולחים: {"message": "מה ביקשתי בפנייה L-1001?", "name": "אורח", "email": "you+guest@gmail.com", "thread": "guest-1"}
שאלה למחשבההסוכן ענה? עם פרטי רונית — טלפון, תקציב? ומי שאל? "אורח", עם אימייל אחר לגמרי. ומה אם מישהו יכתוב לו "תביא את https://…"?
מה הבעיה ואיך מתקנים?

שתי בעיות: 1) כל אחד יכול לקבל פרטים של כל לקוח — אין בדיקה שהשואל הוא בעל הפנייה. 2) ה-URL בידי הסוכן — הוא יכול לפנות לכל כתובת. תיקון: URL קבוע עם https://weizmann.ai/demo/api/v1/leads/ ורק המספר בידי הסוכן, ובהוראות: "מוסרים פרטי פנייה רק אם האימייל של השואל זהה לאימייל בפנייה". והכי טוב: Filter ב-Make אחרי הכלי — לא רק פרומפט.
