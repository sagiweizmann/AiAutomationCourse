חלק 1 · Skills

Skill: חוברת הדרכה שנפתחת רק כשצריך

במפגש 9, כל הכללים של נועם נכנסו להוראות המערכת. זה עובד עם 6 כללים, אבל לא עם 6 תחומי מומחיות. Skill היא תיקייה עם קובץ SKILL.md (הוראות), ולפעמים גם תבניות, קבצי עזר וסקריפטים. Claude רואה בהתחלה רק את השם והתיאור של כל Skill, וקורא את השאר רק כשהבקשה מתאימה. Anthropic קוראת לזה חשיפה הדרגתית (Progressive disclosure).

סימולציה

מה נכנס לחלון ההקשר?

טוקנים שנכנסים לכל בקשה, לפני שהלקוח כתב מילה:
שם ותיאורהוראות SKILL.mdקבצי עזר ופלט סקריפטהכול, בלי קשר לבקשה
איפה Skills עובדותב-Claude (באפליקציה מעלים קובץ ZIP בהגדרות, בתוכניות בתשלום ועם הרצת קוד מופעלת), ב-Claude Code, ב-Claude API וב-Agent SDK. Skill שהעליתם במקום אחד לא מסונכרנת לשאר. ובטיחות: Skill היא כמו תוכנה שמתקינים, ולכן משתמשים רק ב-Skills שכתבתם בעצמכם או שקיבלתם ממקור מהימן.
חלק 2 · MCP

MCP: שקע אחד לכל המערכות

MCP (Model Context Protocol) הוא תקן פתוח שבנתה Anthropic, וכיום משתמשים בו גם כלים של חברות אחרות. מערכת שרוצה לעבוד עם סוכנים כותבת שרת MCP אחד. כל אפליקציה שתומכת ב-MCP, כמו Claude, Claude Code או Agent SDK, יכולה להתחבר אליו. בלי תקן כזה, צריך לבנות חיבור נפרד לכל צמד של כלי AI ומערכת.

מה שרת MCP חושף:

🔧 Tools · כליםפעולות שהסוכן יכול להפעיל, כמו get_order_status, ‏send_message ו-run_scenario. כמו הכלים ממפגש 9.
📄 Resources · משאביםמידע לקריאה, כמו קבצים, רשומות וטבלאות, שהאפליקציה יכולה להכניס להקשר.
📝 Prompts · תבניותתבניות פרומפט מוכנות שהשרת מציע, למשל "סכם את הקריאות הפתוחות".
איך זה מתחבר למה שכבר בניתםה-Connectors שהכרתם במפגש 7 מבוססים על MCP. ב-Claude אפשר להוסיף Connector מותאם אישית: מדביקים כתובת URL של שרת MCP מרוחק, ומאשרים גישה. Make, וגם מערכות CRM וכלי עבודה רבים, מציעים שרת MCP. כך התרחישים שבניתם במפגש 9 יכולים להפוך לכלים של Claude בצ'אט. הזמינות והתוכניות משתנות, ולכן בדקו בחשבון שלכם.
שרת MCP הוא הרשאהכל מה שראינו במפגש 9 על הרשאות והזרקת פרומפט חל גם כאן. מחברים רק שרתים מהימנים, נותנים לכל שרת את ההרשאות המינימליות, ובודקים אילו כלים הוא חושף. תוצאה שחוזרת משרת MCP היא מידע, לא הוראות.
חלק 3 · זיכרון

זיכרון: הלקוחה חוזרת, ונועם זוכר

Claude לא זוכר שום דבר בין קריאות. כל "זיכרון" הוא מידע שהמערכת שלכם שומרת, ומחזירה לו בפעם הבאה. השאלה היא מה לשמור, איפה, ומתי לטעון אותו.

🗨️ בתוך השיחהההודעות הקודמות נשלחות שוב בכל קריאה. נגמר כשהשיחה נגמרת, או כשחלון ההקשר מתמלא.
🗂️ בין שיחותקובץ או שורה לכל לקוח, עם עובדות קצרות שנטענות בתחילת שיחה חדשה. ב-API יש לזה כלי מובנה (Memory tool), עם תיקיית /memories אצלכם.
📚 ידע כללימה שנכון לכל הלקוחות, כמו מדיניות ומוצרים. זה בסיס הידע ממפגש 8, לא זיכרון.
סימולציה

שלוש שיחות עם מיכל

קובץ הזיכרון של מיכל
זיכרון הוא גם סיכוןלא שומרים פרטים רגישים, כמו אמצעי תשלום, בריאות או מספרי זהות. לא שומרים "עובדות" שהלקוח טוען ושלא אומתו, כמו "הבטיחו לי הנחה". זו הרעלת זיכרון (Memory poisoning): הזרקה שנשארת לשיחות הבאות. וקובעים מתי מוחקים: לקוח שלא פנה שנה, או לקוח שביקש למחוק את המידע עליו.
חלק 3 · Claude Agent SDK

סוכן בקוד: Claude Agent SDK

Claude Agent SDK היא ספרייה (Python או TypeScript) שמריצה את אותה לולאת סוכן שמפעילה את Claude Code. הלולאה, ניהול ההקשר, ההרשאות, MCP ו-Skills מוכנים מראש. אתם כותבים רק את ההוראות, את הכלים ואת הגבולות. לחצו על המספרים כדי לעבור על נועם, בגרסת קוד.
