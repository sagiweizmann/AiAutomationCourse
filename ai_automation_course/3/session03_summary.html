200 / 201 הצלחה: ממשיכים בתהליך
400 בקשה שגויה: בודקים את ה-JSON ואת שדות החובה

429 עומס: מחכים ומנסים שוב
500+ תקלה בשרת: מנסים שוב, ואם לא עובד שולחים התראה

כללי אצבע

חמישה כללים לעבודה עם API

  1. כשמשהו לא עובד, קודם מסתכלים על קוד הסטטוס. הוא אומר איפה לחפש את הבעיה.
  2. בודקים כל בקשה ב-Postman לפני שבונים אותה ב-Make.
  3. מפתחות שומרים רק במשתנים סודיים, ומגדירים מגבלת הוצאה בכל חשבון.
  4. כשאפשר, משתמשים ב-Webhook. זה מהיר יותר וחוסך פעולות.
  5. מבקשים מ-Claude פלט JSON בלבד, ובודקים שהוא תקין לפני שממשיכים בתהליך.
בדיקה עצמית

6 שאלות: מה נשאר לכם מהמפגש?

1. מה הנתיב לשם המוצר השני בהזמנה: {"items":[{"name":"ספה"},{"name":"כרית"}]}?
הסבר: מערכים נספרים מ-0, ולכן המוצר השני הוא items[1]. (ב-Make הספירה מתחילה מ-1.)
2. איזו שיטת HTTP מתאימה ליצירת ליד חדש ב-CRM?
הסבר: POST יוצרת רשומה חדשה. GET רק קוראת נתונים.
3. קיבלתם קוד 401. מה הסיבה הסבירה?
הסבר: 401 פירושו שהשרת לא זיהה אתכם. ניסיון חוזר לא יעזור, צריך לתקן את המפתח.
4. מה היתרון של Webhook על Polling?
הסבר: ב-Webhook המערכת שולחת הודעה ברגע שמשהו קורה. ב-Polling שואלים שוב ושוב, וחלק גדול מהתשובות ריקות.
5. איפה נמצא הטקסט ש-Claude כתב בתשובה של ה-API?
הסבר: התשובה נמצאת במערך content, והטקסט עצמו בשדה text של האיבר הראשון.
6. איפה נכון לשמור מפתח API של Claude?
הסבר: מפתח הוא כמו סיסמה. שומרים אותו במקום מאובטח אחד, ומגדירים מגבלת הוצאה.
