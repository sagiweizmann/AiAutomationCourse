בקשו מקרה אמיתי — לא "איך זה בדרך כלל"

הטריק החשובמבקשים לעבור על המקרה האחרון והאמיתי שטופל, לא על "איך זה עובד בדרך כלל". כך מגלים את השלבים שאף אחד לא כתב בנוהל — ההעתק-הדבק, הבדיקה הקטנה, ההתייעצות בצד.

"בדרך כלל" = התהליך שרוצים שיהיה. "המקרה האחרון" = התהליך שבאמת קורה. את השני ממפים.

חלק 2 · API

API: מלצר בין שתי מערכות

הלקוח (Make) לא נכנס למטבח (מסד הנתונים). הוא מוסר הזמנה למלצר (ה-API), והמלצר חוזר עם מנה (התשובה).

שיטהמה היא עושהדוגמה
GETקריאת נתוניםלהביא את הזמנה 48213
POSTיצירת רשומה חדשהליצור ליד חדש
PUT / PATCHעדכון רשומהלשנות סטטוס ל"נשלחה"
DELETEמחיקהלבטל הזמנה

כל בקשה כוללת: שיטה, כתובת (Endpoint), כותרות (Headers, כולל המפתח), ולפעמים גוף (Body) ב-JSON.

  • המטאפורה של המלצר עובדת טוב. ה-API מסתיר את המורכבות ונותן דרך מוסדרת לבקש.
  • 4 השיטות מספיקות ל-95% מהמקרים. ב-Make בוחרים אותן מרשימה.

חלק 3 · אבטחה

איך ה-API יודע מי אתם

🔑 מפתח API

מחרוזת סודית שנשלחת בכותרת של כל בקשה. כמו מפתח לבניין: מי שמחזיק בה נכנס. Claude API עובד כך.

🎫 OAuth

המשתמש מאשר לאפליקציה גישה מוגבלת, בלי למסור סיסמה. כמו מפתח חניון: מתניע את הרכב, לא פותח את תא המטען. כך Make מתחבר ל-Gmail.

מפתח API הוא כמו סיסמהלא מדביקים אותו במסמך משותף, בצילום מסך או בוואטסאפ. שומרים במקום מאובטח, מגדירים מגבלת הוצאה, ואם דלף — מבטלים מיד ויוצרים חדש.
  • ההבדל המעשי: מפתח API = אתם מחזיקים סוד. OAuth = המשתמש מאשר, ואפשר לבטל בכל רגע.
  • האזהרה על המפתח חשובה מאוד — זו טעות אבטחה נפוצה של מתחילים.

תרגיל: Claude מחלץ נתונים ל-JSON

⏱ כ-15 דקותעם Claude

פתחו את Claude בצ'אט, הדביקו את הפרומפט, ואז נסו הודעות לקוח משלכם. זה בדיוק מה ש-Make ישלח דרך API.

אתה מחלץ נתונים מפניות לקוחות של "בית ועיצוב". החזר JSON בלבד (בלי טקסט מסביב) עם השדות: customer_name, order_id, topic (אחד מ: delivery / defect / refund / other), urgency (low / high). הפנייה: "שלום, מדברת רונית שגב. ההזמנה שלי (50912) הייתה אמורה להגיע אתמול ולא הגיעה, ואני צריכה אותה דחוף."

⏱ כ-15 דקותעם Claude

השתמשו ב-Claude כשותף לתכנון: תנו לו את ה-As‑Is שלכם ובקשו תוכנית אוטומציה ל-Make.

זה תהליך As‑Is שמיפיתי (הדביקו כאן את השלבים שלכם). אני רוצה להפוך אותו לאוטומציה ב-Make. תכנן לי: 1. מה הטריגר (Webhook / Polling)? 2. אילו מודולים נדרשים ובאיזה סדר? 3. איפה Claude נכנס, ומה הוא מקבל ומחזיר (JSON)? 4. היכן חייבת להיות נקודת אישור של אדם? 5. אילו קודי תשובה צריך לטפל בהם (401 / 404 / 429)? החזר טבלה קצרה של המודולים.
תוכנית אוטומציה מ-Claude לתהליך שלכם, עם הערה אחת שלכם: מה הייתם משנים בה.
  • זה הלב של "תרגול עם Claude לאוטומציות": Claude לא רק מנסח טקסט, הוא עוזר לתכנן את התרחיש.
  • הדגישו את ההערה האישית — Claude מציע, האדם מחליט. אל תקבלו תוכנית בעיניים עצומות.
לפני שמסיימים

בדיקה עצמית לפני שמגישים

  • מסמך אפיון של עמוד אחד, עם As‑Is, To‑Be ו-ROI
  • תרשים זרימה (Mermaid) של התהליך
  • ה-JSON ש-Claude החזיר לשלוש פניות
  • תוכנית אוטומציה מ-Claude, עם הערה אחת שלכם
  • לפחות נקודת אישור אנושית אחת בתוכנית
  • עברו על הרשימה בסוף. זו טיוטה — העיקר שהבינו את המבנה ואת החיבור בין אפיון לטכני.

⚡Webhook מהיר מ-Polling; OAuth שומר על הסיסמה
🤖Claude API מחזיר JSON — והטקסט ב-content[0].text
