חלק 1 · מסמכים

Claude קורא חשבונית, ו-Make בודק אותה

Claude יודע לקרוא PDF ותמונות: חשבוניות, קבלות, טפסים סרוקים וצילומי מסך. הוא מחלץ מהם JSON, בדיוק כמו ממייל. אבל מסמך הוא קלט מסוכן יותר, כי סריקה יכולה להיות מטושטשת ומספרים יכולים להיות שגויים כבר במקור. לכן אחרי החילוץ תמיד יש שלב של אימות. בחרו חשבונית והריצו.

בדיקות של Make
חלוקת העבודהClaude קורא את המסמך. Make מחשב ובודק: האם החשבון מסתדר, האם המספר כבר קיים בגיליון, ומה הסכום. זה הכלל ממפגש 1: חישובים לא עושים במודל.
חלק 1 · איך זה נראה ב-API

שולחים את הקובץ כ"בלוק מסמך"

בצ'אט פשוט מצרפים את הקובץ. ב-API הקובץ נשלח בתוך ההודעה, כטקסט מקודד (base64), לצד ההוראה. ב-Make מורידים את הקובץ (מ-Gmail או מ-Google Drive), מקודדים אותו ל-base64 בעזרת פונקציה של Make, ושולחים במודול HTTP.

{
  "model": "(model name from the docs)",
  "max_tokens": 800,
  "system": "חלץ מהחשבונית JSON בלבד: supplier, invoice_number, date, items[], subtotal, vat, total. אם שדה לא קריא, החזר null.",
  "messages": [{
    "role": "user",
    "content": [
      { "type": "document",
        "source": { "type": "base64", "media_type": "application/pdf", "data": "{{toString(2.data; base64)}}" } },
      { "type": "text", "text": "זו חשבונית ספק. חלץ את הנתונים." }
    ]
  }]
}

לתמונה (JPG או PNG) משתמשים ב-"type": "image" עם media_type מתאים, כמו image/jpeg. את מגבלות הגודל ואת הפורמטים הנתמכים בודקים בתיעוד.

חלק 2 · שלב אישור

אתם הנציגים: אשרו, תקנו או דחו

Claude הכין טיוטות תשובה לארבעה לידים. כל פעולה שלכם מפעילה את Make: אישור שולח את הטיוטה, תיקון שולח את הגרסה המתוקנת ושומר את השינוי, ודחייה מעבירה את הליד לטיפול ידני. שימו לב למדדים.

חלק 3 · בנייה ב-Make

שתי דרכים לבנות שלב אישור

📋 דרך גיליון (פשוטה)

תרחיש A: … ← Sheets·status = "ממתין"

הנציג משנה בגיליון את הסטטוס ל"מאושר", ואם צריך גם מתקן את הטקסט. תרחיש B רץ כל 15 דקות, מחפש שורות במצב "מאושר" שעוד לא נשלחו, שולח אותן ומעדכן את הסטטוס ל"נשלח".

🔗 דרך קישורים במייל (מהירה)

מייל לנציג עם 2 קישורים→Webhook: approve / reject

כל קישור מוביל לכתובת Webhook של תרחיש B, עם פרמטרים: ?row=12&action=approve. בלחיצה התרחיש רץ מיד ושולח. מתאים לאישור מהטלפון, אבל אי אפשר לתקן בו את הטקסט.

אבטחה בקישורי אישורכל מי שמחזיק בקישור יכול ללחוץ עליו. מוסיפים לקישור מחרוזת סודית (token) ובודקים אותה בתרחיש. אחרי לחיצה אחת מסמנים את השורה, כדי שלחיצה שנייה לא תשלח שוב.
