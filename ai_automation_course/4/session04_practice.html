טריגר: Custom webhook

⏱ 15 דקותקל
Webhooks · Custom webhook
  1. ב-Make לחצו Create a new scenario, ושנו את השם ל"לידים מהאתר".
  2. לחצו על ה-+ הגדול, חפשו Webhooks, ובחרו Custom webhook.
  3. לחצו Add, תנו ל-Webhook שם ("lead-form"), שמרו, ולחצו Copy address to clipboard.
  4. לחצו Run once (למטה משמאל). Make ממתין עכשיו לנתונים.
  5. ב-Postman שלחו POST לכתובת שהעתקתם, עם הגוף שבהמשך. ב-Make אמורה להופיע ההודעה "Successfully determined".
  6. לחצו על הבועה שמעל המודול, ובדקו שכל השדות הגיעו.
{
  "full_name": "  נועה כהן ",
  "email": "noa@example.com",
  "phone": "050-1112233",
  "interested_in": "שולחן אלון",
  "source": "website",
  "message": "האם השולחן זמין בצבע אגוז?"
}
שימו לב לרווחיםבשם יש בכוונה רווחים מיותרים בהתחלה ובסוף. נטפל בהם בתרגיל 2.

שמירה בגיליון ומיפוי שדות

⏱ 20 דקותקל
Webhook→Google Sheets · Add a Row
  1. הוסיפו אחרי ה-Webhook את המודול Google Sheets ‹ Add a Row, וחברו את חשבון Google שלכם (זה חיבור OAuth, כמו שראינו במפגש 3).
  2. בחרו את הגיליון "לידים - בית ועיצוב". בשדה Table contains headers בחרו Yes.
  3. מפו את השדות לעמודות: לחצו על כל עמודה, ובחרו את השדה המתאים מהחלון הצף.
  4. בעמודת התאריך השתמשו בפונקציה: formatDate(now; "DD/MM/YYYY HH:mm")
  5. בעמודת השם עטפו את השם ב-trim(...).
  6. הריצו שוב (Run once ושליחה מ-Postman), ובדקו שהשורה בגיליון נקייה.
התאריך יוצא בשעה לא נכונה?בדקו את אזור הזמן בהגדרות הפרופיל או הארגון ב-Make, וכוונו אותו ל-Asia/Jerusalem.

Router, מסננים ומסלול ברירת מחדל

⏱ 25 דקותבינוני
Webhook→Router→① יש טלפון: Sheets + מייל ללקוח→② אין טלפון: מייל לנציג
  1. הכניסו Flow Control ‹ Router בין ה-Webhook לבין Sheets (קליק ימני על הקו ‹ Add a router).
  2. מסלול 1: לחצו על הקו, בחרו Set up a filter, ותנו לו את השם "יש טלפון". התנאי: phone + Exists. במסלול הזה נמצא מודול ה-Sheets, ואחריו מודול מייל שמודה ללקוח.
  3. מסלול 2: מסנן "אין טלפון" עם התנאי phone + Does not exist. במסלול הזה שולחים מייל אליכם (בתור הנציג) עם הנושא "חסר טלפון לליד: {{full_name}}".
  4. מסלול 3 (ברירת מחדל): הוסיפו מסלול שלישי, ובהגדרות המסנן שלו סמנו Fallback route: Yes. בו שולחים התראה "ליד לא מסווג".
  5. שלחו מ-Postman את שני הלידים (נועה מתרגיל 1 ודני מהגוף שבהמשך), ובדקו שכל אחד מהם הלך למסלול הנכון.
{
  "full_name": "דני לוי",
  "email": "dani@example.com",
  "phone": "",
  "interested_in": "ספה תלת",
  "source": "facebook",
  "message": "מה המחיר עם משלוח?"
}
דני עבר במסלול "יש טלפון", למרות שאין לו טלפוןאצל דני השדה phone קיים, אבל הוא ריק (""). ב-Make, Exists בודק שיש ערך. אם זה לא עובד אצלכם, נסו את התנאי length(phone) + Greater than + 0.
אין לכם Gmail?אפשר להשתמש במודול Email ‹ Send an email של Make, או לשלוח הודעה ל-Slack.
צילום מסך של התרחיש עם שלושת המסלולים, ושל ה-History עם שתי ההרצות

Iterator ו-Text aggregator: הזמנה עם כמה מוצרים

⏱ 25 דקותבינוני
Webhook (orders)→Iterator→Sheets · Add a Row→Text aggregator
  1. צרו תרחיש חדש "פריטי הזמנה", עם Custom webhook חדש בשם "orders". בגיליון צרו לשונית בשם "פריטים", עם העמודות: מספר הזמנה, לקוח, מוצר, כמות, מחיר, סה"כ.
  2. שלחו מ-Postman את ההזמנה שבהמשך, כדי ש-Make יזהה את המבנה שלה.
  3. הוסיפו Flow Control ‹ Iterator, ובשדה Array מפו את items.
  4. הוסיפו Google Sheets ‹ Add a Row ללשונית "פריטים". מפו את שם המוצר, הכמות והמחיר מה-Iterator, ואת מספר ההזמנה והלקוח מה-Webhook. בעמודה סה"כ חשבו: qty * price.
  5. הוסיפו Tools ‹ Text aggregator. בשדה Source module בחרו את ה-Iterator, ובשדה Text כתבו: name ×qty (עם המיפוי של השדות). בשדה Row separator בחרו New row.
  6. הריצו ובדקו: כמה שורות נוספו לגיליון? מה יצא מה-Aggregator? כמה פעולות נספרו?
{
  "order_id": 50913,
  "customer": "רונית שגב",
  "items": [
    { "name": "כיסא בר", "qty": 3, "price": 390 },
    { "name": "כרית נוי", "qty": 2, "price": 79 },
    { "name": "מנורת עמידה", "qty": 1, "price": 890 }
  ]
}
צילום מסך של 3 השורות בגיליון, הפלט של ה-Aggregator, ומספר הפעולות

טיפול בשגיאות

⏱ 20 דקותמאתגר

נדמה שירות חיצוני שנופל. בתרחיש של תרגיל 3, במסלול 1, אחרי מודול ה-Sheets:

  1. הוסיפו מודול HTTP ‹ Make a request שקורא ל-https://httpbin.org/status/500 (שיטה GET). זה "שירות" שתמיד מחזיר שגיאת שרת.
  2. הריצו פעם אחת ותראו מה קורה בלי טיפול בשגיאה.
  3. בהגדרות התרחיש (Scenario settings) הפעילו את Allow storing of incomplete executions.
  4. קליק ימני על מודול ה-HTTP ‹ Add error handler ‹ Break. הגדירו 3 ניסיונות, עם הפסקה של דקה בין ניסיון לניסיון.
  5. הריצו שוב, והיכנסו ללשונית Incomplete executions. מה רואים שם?
  6. החליפו את ה-Break ב-Resume, עם ערך חלופי status = "crm_unavailable", והריצו. מה ההבדל?
שאלו את Claudeהעתיקו ל-Claude את הודעת השגיאה שקיבלתם, ושאלו: "איזה Error handler ב-Make מתאים לשגיאה כזו, ולמה?". השוו את התשובה שלו לטבלה שבהרצאה.
צילום מסך של Incomplete executions, והסבר של 2-3 משפטים: מתי Break ומתי Resume
